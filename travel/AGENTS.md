# AGENTS.md

> 路由提示（botler-agent）：涉及「旅行 / 旅游 / 去了 / 逛了 / 景点 / 行程 / 游记 / 打卡 / 照片 / 图片 / 时间线」的事件记录或查询消息都属于本项目。凡涉及金额/消费的消息一律归记账项目，本项目不记录任何金额。

> **这是开源模板（botler-agent-app）**：本目录只提供数据格式与约定示例，不含真实数据。示例文件以 `.sample.json` 结尾，仅供参照格式；`scripts/`（`build.py`）已随模板附带，用于从你的 `data/` 生成 `web/map.html` 与 `web/timeline.html`（这些产物内联真实数据，**不提交**）。

## 这是什么

旅行数据子项目：记录旅行中的事件（文字 + 图片 + 地点），后期生成时间线与"我去过哪些地方"地图。**唯一事实来源是 `data/days/` 下按天拆分的文件**。**本项目不存钱**——旅行花费在 ledger 项目记账，用 `旅行:<行程名>` 标签关联，由 build.py 按行程汇总金额。

## 核心约定

- 只记事件 / 见闻 / 行程 / 图片，**不记录任何金额**。凡带金额或消费动词的消息归 ledger 项目。
- 事件写入 `data/days/` 对应日期文件；入站图片由框架自动落盘到 `photos/`，agent 引用项目根相对路径 `photos/<文件名>`。
- **`data/events.json` 是 build.py 生成的聚合产物，不要手改**；想查数据用 `--report`，想改数据改对应日期文件。

## 数据文件

### data/days/YYYY-MM-DD.json —— 唯一事实来源（按天）

每天一个文件；目标日期文件不存在时**新建**（结构如下），不要动其他日期文件：

```json
{
  "date": "2026-08-23",
  "events": [
    {
      "id": "E20260823-001",
      "at": "2026-08-23T14:30:00+08:00",
      "place": "示例景点",
      "city": "北京",
      "trip": "2026示例行程",
      "text": "示例事件描述",
      "images": ["photos/2026-08-23-8f3a9c.jpg"]
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 唯一 ID，`E<YYYYMMDD>-<seq>`，规则同 ledger（当日文件内最大序号 +1） |
| `at` | 事件时间，ISO 8601 含时区，**日期部分必须与文件名一致** |
| `place` | 具体地点（景点/场馆名），可空 |
| `city` | 城市名，与 `data/cities.json` 做后缀归一化匹配；新增城市请同步补进 cities.json（含省份与经纬度） |
| `trip` | 行程名（可空），**与 ledger 的 tag 命名一致**：travel `trip: "2026北京"` ↔ ledger tag `旅行:2026北京` |
| `text` | 事件描述 |
| `images` | 图片路径数组，相对 travel 项目根，存于 `photos/` |

### data/events.json —— 聚合产物（只读）

build.py 把 `data/days/` 所有事件合并后写入这里（按 at + id 排序）。**不要直接编辑**。

### data/cities.json —— 城市表（示例含少量城市，可自行扩展）

```json
{
  "cities": [
    { "city": "北京", "province": "北京市", "lat": 39.9042, "lng": 116.4074 }
  ]
}
```

- 匹配规则：城市名做后缀归一化（去掉 省/市/自治区/特别行政区）后匹配；
- 匹配不上 → build.py 告警并跳过，不阻断构建。

## 图片处理

- 微信渠道：图片由框架自动落盘到 `photos/`，写事件时把项目内相对路径（如 `photos/2026-08-23-xxxx.jpg`）写进 `images` 数组。
- 其他渠道（Telegram / Feishu / CLI）：图片需用户手动放入 `photos/`，agent 按文件名引用。
- 未被任何事件引用的孤儿图片由 build.py 输出清单，定期人工清理。

## 如何记录事件（写）

1. `read data/days/<事件日期>.json`；不存在则按上面结构新建。
2. 在该文件 `events` 数组里**追加**一条事件：`id` 取当日最大序号 +1。
3. 写回该日期文件，然后执行 `python3 scripts/build.py`，确认校验通过、时间线/地图已刷新。

## 如何查询（只读）

**回顾/统计类消息直接跑 `python3 scripts/build.py --report <查询>`**，不要逐文件 read：

| 查询 | 例子 | 返回 |
|---|---|---|
| 某天 | `--report 2026-08-23` | 当天所有事件（时间/地点/行程/描述） |
| 某行程 | `--report 行程:2026北京` | 行程天数/城市/事件数 + 旅行支出（从 ledger） |
| 城市足迹 | `--report 城市` | 到访城市及次数 |

## 写入后必须刷新

任何写入 `data/days/` 下文件后执行 `python3 scripts/build.py`，否则 `data/events.json` 聚合与仪表盘不刷新。

## 混合消息仲裁

句子里带金额或真正的消费动词（花了 / 买了 / 付了 / 订了…）→ 该消息归 ledger 项目，本项目不记录，即使含体验描述。纯体验句（无金额）→ 本项目。「门票」等名词单独出现且无金额 → 属本项目。无文字的纯图片消息默认归本项目；若图片内容明显属于其他项目（如菜品图 → cook），按内容路由。
