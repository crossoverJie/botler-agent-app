# AGENTS.md

路由提示（botler-agent）：涉及「记账 / 账 / 消费 / 花了 / 支出 / 收入 / 工资 / 报销 / 账单 / 开销 / 结余」的记录或查询消息都属于本项目。任何涉及金额的消息一律路由到本项目,即使发生在旅行中(旅行消费在记账里打 旅行:<行程名> 标签)。

## 这是什么

个人记账数据子项目。**唯一事实来源是 `data/days/` 下按天拆分的文件**,支持按月份 / 分类 / 标签 / 账户 / 交易对象 / **付款人** 多维度统计。消费类消息路由到这里;旅行项目不存钱。

## 核心约定

- **钱只进本项目**。任何金额都记到 `data/days/` 对应日期的文件,总额永远完整。
- **一条消息只记一种账**;转账(transfer)暂不支持,`type` 只有 `expense` / `income` / `refund`(退款,见下文「退票 / 退款怎么记」)。
- 金额用**整数分**存储:元 → 分 = ×100(如 25.90 元 → `amount_cents: 2590`,200 元 → `20000`)。禁止小数、禁止字符串金额。
- **`data/ledger.json` 是 build.py 生成的聚合产物,不要手改**;手改会被 build.py 下次运行覆盖。

## 数据文件

### data/days/YYYY-MM-DD.json —— 唯一事实来源(按天)

每天一个文件;目标日期文件不存在时**新建**(结构如下),不要动其他日期文件:

```json
{
  "date": "2026-08-23",
  "records": [
    {
      "id": "L20260823-001",
      "date": "2026-08-23",
      "type": "expense",
      "amount_cents": 20000,
      "account": "微信",
      "category": ["餐饮", "午餐"],
      "tags": ["旅行:2026北京"],
      "payer": "我",
      "payee": "全聚德",
      "note": "北京旅行午餐",
      "created_at": "2026-08-23T12:30:00+08:00"
    }
  ]
}
```

字段说明:

| 字段 | 说明 |
|---|---|
| `id` | 唯一 ID,`L<YYYYMMDD>-<seq>`;`seq` 为**该日期文件内**已有记录最大序号 +1(如当日已有 -001/-002,新记录为 -003);跨天唯一性由 build.py 兜底校验 |
| `date` | 实际交易日,`YYYY-MM-DD`,**必须与文件名一致** |
| `type` | `expense`(支出)/ `income`(收入)/ `refund`(退款:退回的钱,正数分) |
| `amount_cents` | 金额,**正整数分**,见上方换算规则 |
| `account` | 取 `data/meta.json.accounts`;用户未指定时默认「微信」 |
| `category` | 分类路径,**父级在前**(如 `["餐饮","午餐"]`);必须完整存在于 `meta.json.categories` |
| `tags` | 标签数组;**旅行消费统一用 `旅行:<行程名>`**(如 `旅行:2026北京`)。新行程首笔记账前,先把 `旅行:<名>` append 进 `meta.json.tags` 登记表再写记录 |
| `payer` | **付款人**,取 `data/meta.json.payers`;用户未指定时默认「我」。用于区分"我付"与"他人(如女友)代付」。统计行程总花费时按此拆分;多人共付场景(如旅行)必填。不写视为「我」 |
| `payee` / `note` | 交易对象 / 备注,可空 |
| `created_at` | 记录创建时间,ISO 8601 带时区(`+08:00`),如 `2026-08-26T09:41:00+08:00`。**Agent 没有自己的时钟:写入每条记录前先 `run` 执行 `scripts/now.py`,用其输出作为 `created_at`。** 用户明确说了时间(如「早上8点花的」)才用用户说的;否则一律用当前时间,**不要编造/猜测时间**(run 工具只能跑 .py/.js/.mjs 脚本,跑不了 `date` 等 shell 命令)。web 抽屉会展示为「创建时间」。 |

### data/ledger.json —— 聚合产物(只读)

build.py 把 `data/days/` 所有记录合并后写入这里(按日期 + id 排序)。**不要直接编辑**;想查数据用下面的 `--report`,想改数据改对应日期文件。

### data/meta.json —— 分类树 / 账户 / 行程标签 / 付款人 登记表

写入分类 / 账户 / **付款人** 前必须从这里取值,**不发明新分类、新账户、新付款人**。`category` 回答"花在**哪类东西**上",`tag 旅行:<行程名>` 回答"属于**哪趟行程**",`payer` 回答"**谁付的钱**"(我 / 女友),三者**正交**,互不替代:

- 旅行中的午饭 → `["餐饮","午餐"]` + `tag 旅行:2026北京` + `payer:"我"`(或 `"女友"`);
- 机票 → `["交通","机票"]` + 同一个 tag + 相应 `payer`;
- 只有门票 / 纪念品才用 `["旅行", …]` 分类。

新增付款人(如 `"女友"`)时,先把名字 append 进 `meta.json.payers` 登记表再写记录;`build.py` 会校验 `payer` 必须在此表中,防止拼写漂移。

**收入记录**用「收入」分类,如工资 → `["收入","工资"]`、理财收益 → `["收入","理财"]`;不要再挂 `["其他"]`。

否则行程分类明细会退化,看不出钱花在哪类东西上。

### 退票 / 退款怎么记

`refund` 表示一笔**退回的钱**(如机票退票、订单退款),`amount_cents` 为退回金额(正数分),在聚合时当作**负支出**冲减对应分类 / 行程 / 账户 / 付款人。原始支出记录保持不变。

- **分类 / 标签 / 付款人必须与原支出一致**,这样退款才能正确对冲(如原机票 `["交通","机票"]` + `tag 旅行:2026北京`,退票也用同样的 `category` / `tags` / `payer`)。
- **全额退款**:原支出 ¥1000 + 退票 `refund` ¥1000 → 净支出 0,行程总花费自动扣回。
- **部分退款(扣手续费)**:原支出 ¥1000 + 退票 `refund` ¥900 + 手续费单独一笔 `expense`(如 `["手续费"]` 或挂原分类)¥100 → 净支出 ¥100。手续费是真实支出,**不要混进 `refund`**。
- 退款记录通常记在**实际收到退款的日期**,与原支出可不同天;`type` 写 `refund`,**不要用 `income`**(会污染总收入 / 储蓄率,且不会扣减行程总花费)。

## 如何记账(写记录)

1. `read data/days/<今天或用户指定日期>.json`;文件不存在则按上面结构新建。
2. 在该文件的 `records` 里**追加**一条记录:`id` 取当日最大序号 +1,分类/账户从 `meta.json` 取值,金额转整数分。若款项由他人代付(如女友),`payer` 填对应名字且确保已在 `meta.json.payers` 登记;**自己付则省略 `payer`(默认「我」)**。
3. 写回该日期文件,然后执行 `python3 scripts/build.py`(先 `--dry-run` 更稳),确认校验通过、仪表盘已刷新。

## 如何查询(只读,不要 read 全部数据)

**统计/回顾类消息直接跑 `python3 scripts/build.py --report <查询>`**,返回文本结果,不要逐文件 read(账多之后全量 read 会消耗大量上下文):

| 查询 | 例子 | 返回 |
|---|---|---|
| 总览 | `--report 总览` | 全部收支/结余/分类 Top |
| 本月 / 上月 / 今年 | `--report 本月` | 该周期收支 + 分类 Top |
| 行程 | `--report 旅行:2026北京` | 行程总花费 / 天数 / 日均 / **按付款人拆分** / 分类明细 |
| 分类 | `--report 分类:交通` | 分类净支出合计 + 最近 10 笔明细(退款标 `(退)`) |
| 最近 N 笔 | `--report 最近5` | 最近 N 笔流水(`退` 为退款,非「我」付款带 `@付款人` 标注) |
| 账户 | `--report 账户` | 各账户净支出(退款已冲减) |
| 付款人 | `--report 付款人` / `--report 付款人:女友` | 按付款人拆分全部净支出 / 某付款人全部净支出 |

## 写入后必须刷新

任何写入 `data/days/` 下文件后执行 `python3 scripts/build.py`(可先 `--dry-run` 校验),否则 `data/ledger.json` 聚合不刷新。仪表盘 `web/dist/index.html` 由前端工具链构建(见下「构建与运行」),**不会**被 build.py 自动更新——改完数据后需另跑 `make`(或 `cd web && npm run build`)才会刷新仪表盘。

- **记账后附一句话轻观察（由大模型生成，非固定模板）**：每次成功写入 `data/days/` 并跑完 `build.py` 后，在汇报确认之外，另用**一句话**对本次记账做轻观察/提醒。**做法**：基于刚写入的这条记录 + 当天 `data/days/YYYY-MM-DD.json`（已读写的）来写——某分类今日累计偏高→「今天餐饮花得有点多，悠着点」；大额支出→「这笔不小，确认下有没有更省的」；退款/收入→一句轻松备注；都平常→自然收尾（如「记好了」即可，不硬凑提醒）。**约束**：一句话、口语、像朋友随口说、**每次措辞可以不同**、不罗列、不分行。只读当天文件，不读 `ledger.json`、不跑全量 `--report`，token 可控。

## 构建与运行

本项目分两层,职责清晰、互不耦合:

1. **数据管道(纯 Python,无前端依赖)**:`python3 scripts/build.py` —— 合并 `data/days/` → 校验 → 写聚合产物 `data/ledger.json` → `--report` 文本查询。无 Node 环境也能用校验 / 聚合 / 文本查询,只是仪表盘不更新。
2. **仪表盘前端(Vite + TypeScript + ECharts,单文件离线 HTML)**:`make`(或 `cd web && npm run build`)把 `data/ledger.json` 内联进 `web/dist/index.html`,双击即可离线打开,无外部请求。

- **新克隆机器需先 `make` 一次**才会生成 `web/dist/index.html`(仓库只提交源码与 `web/package-lock.json`,`web/dist/`、`web/node_modules/` 不入库;旧提交里的 `web/ledger.html` 已废弃删除,属一次性迁移)。
- **刷新仪表盘需要 Node 工具链**:`make` 内部先跑一遍 `python3 scripts/build.py` 刷新 `data/ledger.json`,再 `vite build` 生成单文件。日常 `make` 不重装依赖;首次(无 `web/node_modules/`)会自动 `npm ci`。
- **dev 热更新**:`npm run dev` 期间改 `data/days/` 后,需另跑 `python3 scripts/build.py` 刷新 `ledger.json`,vite 才会重新加载(若未生效则重启 dev)。
- **聚合对账**:`npm run parity`(tsx 运行 `web/scripts/parity.ts`)把前端聚合 `src/utils/aggregate.ts` 与 `python3 scripts/build.py --aggregates-json` 的 `compute_*` 输出逐项比对,防止口径漂移。

## 混合消息仲裁

句子里只要带金额或真正的消费动词(花了 / 买了 / 付了 / 订了 / 花了多少钱…),一律按记账处理;其中的体验描述不记录(理想情况用户分两条发)。「门票」等名词单独出现且无金额(如"故宫门票拍得真好看")不判为消费,不记录。
