# AGENTS.md

> 路由提示（botler-agent）：涉及「记账 / 账 / 消费 / 花了 / 支出 / 收入 / 工资 / 报销 / 账单 / 开销 / 结余」的记录或查询消息都属于本项目。任何涉及金额的消息一律路由到本项目，即使发生在旅行中（旅行消费在记账里打 `旅行:<行程名>` 标签）。

> **这是开源模板（botler-agent-app）**：本目录只提供数据格式与约定示例，不含真实数据。示例文件以 `.sample.json` 结尾，仅供参照格式；`scripts/`（如 `build.py`）由使用者自行提供，本模板不包含脚本源码。

## 这是什么

个人记账数据子项目。**唯一事实来源是 `data/days/` 下按天拆分的文件**，支持按月份 / 分类 / 标签 / 账户 / 交易对象 / **付款人** 多维度统计。消费类消息路由到这里；旅行项目不存钱。

## 核心约定

- **钱只进本项目**。任何金额都记到 `data/days/` 对应日期的文件，总额永远完整。
- **一条消息只记一种账**；`type` 只有 `expense` / `income`。
- 金额用**整数分**存储：元 → 分 = ×100（如 25.90 元 → `amount_cents: 2590`，200 元 → `20000`）。禁止小数、禁止字符串金额。
- **`data/ledger.json` 是 build.py 生成的聚合产物，不要手改**；手改会被 build.py 下次运行覆盖。

## 数据文件

### data/days/YYYY-MM-DD.json —— 唯一事实来源（按天）

每天一个文件；目标日期文件不存在时**新建**（结构如下），不要动其他日期文件：

```json
{
  "date": "2026-08-23",
  "records": [
    {
      "id": "L20260823-001",
      "date": "2026-08-23",
      "type": "expense",
      "amount_cents": 20000,
      "account": "微信",
      "category": ["餐饮", "午餐"],
      "tags": ["旅行:2026北京"],
      "payer": "我",
      "payee": "示例餐厅",
      "note": "示例午餐",
      "created_at": "2026-08-23T12:30:00+08:00"
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `id` | 唯一 ID，`L<YYYYMMDD>-<seq>`；`seq` 为**该日期文件内**已有记录最大序号 +1；跨天唯一性由 build.py 兜底校验 |
| `date` | 实际交易日，`YYYY-MM-DD`，**必须与文件名一致** |
| `type` | `expense`(支出) / `income`(收入) |
| `amount_cents` | 金额，**正整数分**，见上方换算规则 |
| `account` | 取 `data/meta.json.accounts`；用户未指定时默认「微信」 |
| `category` | 分类路径，**父级在前**（如 `["餐饮","午餐"]`）；必须完整存在于 `meta.json.categories` |
| `tags` | 标签数组；**旅行消费统一用 `旅行:<行程名>`**（如 `旅行:2026北京`）。新行程首笔记账前，先把 `旅行:<名>` append 进 `meta.json.tags` 登记表再写记录 |
| `payer` | **付款人**，取 `data/meta.json.payers`；用户未指定时默认「我」。用于区分"我付"与"他人代付"。统计行程总花费时按此拆分；多人共付场景（如旅行）必填。不写视为「我」 |
| `payee` / `note` | 交易对象 / 备注，可空 |

### data/ledger.json —— 聚合产物（只读）

build.py 把 `data/days/` 所有记录合并后写入这里（按日期 + id 排序）。**不要直接编辑**；想查数据用 `--report`，想改数据改对应日期文件。

### data/meta.json —— 分类树 / 账户 / 行程标签 / 付款人 登记表

写入分类 / 账户 / **付款人** 前必须从这里取值，**不发明新分类、新账户、新付款人**。`category` 回答"花在**哪类东西**上"，`tag 旅行:<行程名>` 回答"属于**哪趟行程**"，`payer` 回答"**谁付的钱**"，三者**正交**，互不替代。

新增付款人时，先把名字 append 进 `meta.json.payers` 登记表再写记录；`build.py` 会校验 `payer` 必须在此表中，防止拼写漂移。

**收入记录**用「收入」分类，如工资 → `["收入","工资"]`、理财收益 → `["收入","理财"]`；不要再挂 `["其他"]`。

## 如何记账（写记录）

1. `read data/days/<今天或用户指定日期>.json`；文件不存在则按上面结构新建。
2. 在该文件的 `records` 里**追加**一条记录：`id` 取当日最大序号 +1，分类/账户从 `meta.json` 取值，金额转整数分。若款项由他人代付，`payer` 填对应名字且确保已在 `meta.json.payers` 登记；自己付则省略 `payer`（默认「我」）。
3. 写回该日期文件，然后执行 `python3 scripts/build.py`（先 `--dry-run` 更稳），确认校验通过。

## 如何查询（只读）

**统计/回顾类消息直接跑 `python3 scripts/build.py --report <查询>`**，返回文本结果，不要逐文件 read：

| 查询 | 例子 | 返回 |
|---|---|---|
| 总览 | `--report 总览` | 全部收支/结余/分类 Top |
| 本月 / 上月 / 今年 | `--report 本月` | 该周期收支 + 分类 Top |
| 行程 | `--report 旅行:2026北京` | 行程总花费 / 天数 / 日均 / 按付款人拆分 / 分类明细 |
| 分类 | `--report 分类:交通` | 分类支出合计 + 最近 10 笔明细 |
| 最近 N 笔 | `--report 最近5` | 最近 N 笔流水 |

## 写入后必须刷新

任何写入 `data/days/` 下文件后执行 `python3 scripts/build.py`（可先 `--dry-run` 校验），否则 `data/ledger.json` 聚合与仪表盘不刷新。

## 混合消息仲裁

句子里只要带金额或真正的消费动词（花了 / 买了 / 付了 / 订了…），一律按记账处理；其中的体验描述不记录。「门票」等名词单独出现且无金额不判为消费，不记录。
